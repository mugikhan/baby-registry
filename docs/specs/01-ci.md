# Spec 01: CI

Slice 1 of the [PRD](../../Baby%20Registry%20—%20PRD.md) delivery plan. Status: ready for agent.

## Problem Statement

The registry has no automated checks. Lint, format, type and test failures surface only when the developer runs them by hand. A pull request can merge into main with a failing test.

## Solution

GitHub Actions runs the existing checks and tests on every pull request into main and every push to main. One job does it all. The job is free to run and needs no secrets.

## User Stories

1. As the developer, I want CI to run on every pull request into main, so that I see failures before I merge.
2. As the developer, I want CI to run on every push to main, so that I know main is green after a merge.
3. As the developer, I want CI to run `pnpm check`, so that format, lint, type and unit test failures fail the run.
4. As the developer, I want CI to run the Playwright suite on all three projects, so that a page that breaks at 360 px fails the run.
5. As the developer, I want a new push to a pull request to cancel the older run, so that I wait only for the latest result.
6. As the developer, I want CI to cost nothing, so that the registry stays inside the PRD's R0 budget.

## Implementation Decisions

- One workflow with one job on `ubuntu-latest`. It triggers on `pull_request` into main and `push` to main.
- Steps, in order:
  1. Check out the code.
  2. Set up pnpm from the `packageManager` field.
  3. Set up Node 24 with the built-in pnpm cache.
  4. `pnpm install --frozen-lockfile`.
  5. `pnpm check`.
  6. Install the Playwright browsers the projects need (Chromium and WebKit) with their system packages.
  7. Apply local D1 migrations.
  8. `pnpm test:e2e`.
- E2E uses the existing Playwright config, which starts the dev server. Set `forbidOnly` when running in CI, so a leftover `test.only` fails the run.
- The token is read-only (`contents: read`). The job uses no secrets. Each job has a 15-minute timeout.
- A concurrency group per git ref cancels an outdated pull request run.
- Cost: the repo is public, and GitHub does not charge public repos for standard GitHub-hosted Linux runners. The job uses no paid actions or services. If the repo ever becomes private, the free plan's monthly minutes apply.
- The README gets two lines: what CI runs, and that it is free while the repo is public.

## Testing Decisions

- The test is the check on a real pull request. The pull request that adds the workflow must show the job green.
- Prior art: the existing Vitest settings test and Playwright smoke test are the suites CI runs. This slice adds no new tests.

## Out of Scope

- Deploy jobs and secrets. They come in slice 4.
- Lighthouse and the JS budget. They come in slice 3.
- Parallel jobs, browser caching, workflow linters, Dependabot and branch protection. They aren't worth it for a site of this size.
